## 2. Холст, цвет, шрифты

- 1920×1080, 25 fps, yuv420p, BT.709 limited.
- Исходники помечены bt470bg (BT.601). Перевод 601→709 — **ровно один раз, на входе**
  (`scale=…:in_color_matrix=bt601:out_color_matrix=bt709`), в клипах `public/…/clips/*.mp4`.
- Главный кадр Zoom режется из 4K в 2560×1440 (запас под наезд 1,6×), камера — из 4K-плитки
  в 640×360 (lanczos + лёгкий unsharp).
- Палитра `tokens.color`; шрифты: Manrope 500–800 (всё основное), Caveat (рукописные подписи
  и дудлы), JetBrains Mono (метки «ГЛАВА 04 · 57:05», «ЧАТ ЭФИРА», «ОПРОС В ЧАТЕ»).
  `Manrope-SemiBold.ttf` из общей папки шрифтов оказался битым — вес 600 брать из `Manrope-var.ttf`.
  Caveat — только полный `fonts/Caveat-var.ttf` (753 глифа). Старый `Caveat-Regular.ttf` —
  подмножество на 109 глифов без строчной латиницы и цифр: латиница в рукописной подписи
  уходила в засечный запасной шрифт (поймано на карточке главы 24.09).

Правила:

1. План меняется по смыслу: смена слайда, начало демо, акцент в речи (слово-якорь из

2. Камера всегда из 4K; увеличивать плитку больше 1,6× нельзя (в face — ровно 1,6×).
3. В режиме «боковая лента» Zoom (P2) столбец участников (x ≥ 3504 в 4K) — полные имена,
   **никогда не показывать**; главный кадр режется x < 3440. Полоса вкладок браузера (y < 152)
   тоже режется или размывается (решение владельца по `vision/scenes.json → sensitive`).
4. Плашка имени, тег и метка «▶ ВИДЕО» ставятся только туда, где под ними пусто (угол слайда
   без текста). Тег привязан к левому верхнему углу **большого** окна плана (в face_xl — к камере,
   не к уменьшенному слайду). На живом интерфейсе (барабан, демо) тегов нет.

## 4. Четыре обработки слайда — чередуются по смыслу

Колода нарисована скетчем: у каждого слайда есть чистый арт 1920×1080 (`deck/art`, карта
слайд → арт в `deck.merged.json → binding.image`) и чистый рендер слайда из PDF. Размытую
Zoom-трансляцию слайда в монтаж не берём — всегда подменяем чистым источником. Демо и живой
интерфейс не трогаем и схемой не подменяем.

**(a) Чистый слайд** — в studio или full; на статичном слайде медленный дрейф 2–3 % за 10 с
(`drift`, направление чередуется: к центру / к левой трети).

**(b) Живой скетч** — слайд рисует себя сам (движок sketch-course-video: скелеты штрихов
`trace.py` → `sketch/NNN.json`, SVG-маски `strokeDashoffset` открывают оригинальный растр).
Сначала длинные контуры, потом штриховка и заливки, затем законченный силуэт; в конце
кроссфейд 8 кадров в чистый слайд. Элементы слайда (Gemini размечает смысловые блоки и слова-
якоря: `style/showcase/gemini_boxes.py`) стартуют **на слове**, которым ведущий их называет,
±2 кадра. Маркер-ручка видна на 1–2 главных элементах слайда, на остальных — без руки.
Когда: первый показ слайда, о котором говорят по пунктам (уровни, шаги, сравнения).
Не больше одного живого скетча подряд без паузы на чистом слайде.

**(c) Анимация внутри слайда** — всё рисуется в координатах слайда и едет вместе с ним
через наезды и морфы (`marks`):

| Пометка | Когда | Вид |
|---|---|---|
| `circle` | «вот это», ключевой пункт, выигравший билет | маркерный овал коралл, 1,12 оборота с перехлёстом, 16 кадров |
| `underline` | фраза-вывод на слайде | двойной маркерный штрих, 12–14 кадров |
| `check` | «сделали», «работает» | галочка, 9 кадров, жёлтая |
| `arrow` | «смотрите сюда» | изогнутая стрелка снаружи к элементу |
| `box`, `strike` | выделить блок / «это устарело» | рамка / зачёркивание |
| `spotlight` | один пункт из плотного слайда | затемнение 50 % всего, кроме пункта |
| `pulse` | цифра или кнопка | мягкое кольцо, два вдоха |

Наезд на деталь (`moves`) — 20–30 кадров easeInOutCubic, потом медленный доезд до 150 кадров,
отъезд 20–36 кадров. Кадр наезда подбирается так, чтобы **край кадра не резал строку текста**
(проверка по разметке: верхний край ниже заголовка, нижний выше следующей подписи).

**(d) Анимация вокруг слайда** — план board: слайд уменьшается до 60 %, по полям сцены
рукописные подписи Caveat, стрелки, которые **входят в слайд и указывают на элемент**
(конец стрелки задаётся в координатах слайда), счётчики с досчётом до числа со слайда,
звёздочки. Стрелка никогда не пересекает текст слайда: ведём её по пустому полю.
Текст подписей — только то, что сказано или написано на слайде.

**Когда что.** По каждому слайду сборщик выбирает обработку по смыслу речи:
перечисление по пунктам → (b); «вот здесь», цифра, вывод → (c); образ, метафора, обещание,
связь с другим → (d); демо и длинный рассказ без опоры на слайд → (a) с дрейфом и лицом.
Ориентир на 2 часа: живой скетч на 25–35 слайдах, пометки на большинстве показанных слайдов
(1–3 на слайд), board 8–15 раз, face на всех 25 «highlights» из `vision/scenes.json`.

## 8. Субтитры — караоке с плашкой

Рисует Remotion (`Captions2.tsx`) в полосе под окном — никогда поверх слайда и лица.

| Параметр | Значение |
|---|---|
| Шрифт | Manrope 700, 44 px, `#F4F1EA`, тень 0 2 10 px |
| Строки | ≤ 2, ≤ 46 знаков, строки выравниваются по длине |
| Реплика | 0,9–5,6 с; новая на паузе ≥ 350 мс или на конце фразы |
| Караоке | ещё не сказанные слова — 42 % яркости; слово загорается за 3 кадра в момент произнесения |
| Плашка | одно ключевое слово на реплику (термины, числа, выводы; не наречия), коралл r 10, растёт слева направо за 5 кадров со старта за 2 кадра до слова; navy-текст идёт ровно по краю плашки (clip-path), без «прыжка» цвета |
| Появление | 3 кадра + подъём 6 px, уход 2 кадра |
| Полоса | studio/board: центр x 760, y 884–1044; face: центр x 656; full: центр x 960, y 944–1052; едет с морфом |

**Цитата-акцент (`heroes`).** На сильной фразе субтитр на 2–4 с заменяется крупной строкой
52–60 px: Manrope 800, ключевое слово кораллом, маркерный штрих снизу. Не чаще раза в 3–4 минуты
и **только если этой фразы нет на слайде**: если она написана на слайде («Мы научили думать
песок» на слайде 29), акцент — маркерный штрих под текстом самого слайда, а субтитры остаются
(в r2 цитата под той же строкой слайда читалась как дубль — Gemini отметил столкновение).

Текст — `transcript/part{1,2}.words.json`. «Э-э», «м-м» выкидываем. **Фамилии частных людей в
субтитры не пишем** (например, на розыгрыше звучит фамилия победительницы — в субтитрах только
имя; `build_captions(drop=…)`). Прозвучавшее, что попадает под правила текста владельца (запрещённые утверждения,
темы, которые он не выносит в публичные тексты, — `materials.rules`), не субтитровать молча и не вырезать молча, а
вынести владельцу на решение.

  4 строк с «…». Команда — коралловый фон и метка «КОМАНДА».
- **Ответ на опрос** («1», «2», «3», буквы) — компактный пузырь 46 px: имя · «ответ» · крупная
  цифра в коралловом чипе. Одновременно голос уходит в карточку опроса (раздел 10).
- **Выделенный** пузырь: 24 px, коралловая рамка и свечение, метка «ВОПРОС ИЗ ЧАТА» — только
  если это вопрос; держится ≥ 8 с, появляется за 1–2 с до ответа ведущего.
- **Реакции Zoom** на сообщение — значок-счётчик в правом верхнем углу пузыря (рисованная
  иконка + число), подпрыгивает при каждой новой реакции.
- В full чата нет; вопрос, на который отвечают, — тост слева снизу над полосой субтитров.
- Приватность: только имя; почта, ник, имя с фамилией частного лица → «Участник»; сообщения с
  почтой, телефоном, ссылкой, @ником, фамилией, названием компании частного лица не показываем.

## 10. Опросы и голосования

Карточка опроса закрепляется сверху колонки чата (пузыри сдвигаются вниз пружиной), слайд не
перекрывает. Состав: «● ОПРОС В ЧАТЕ · N отв.», вопрос Manrope 800 25 px, строки вариантов:
номер в кружке, полоса, число. Каждый голос из чата: полоса дорастает, число подпрыгивает
пружиной; лидер подсвечивается кораллом; за 2 с до конца опроса лидер получает коралловый
кружок. Уход — 12 кадров.

Какие опросы (из `chat/chat_stats.json → polls`, 16 шт.): таблетка К/С в начале и в финале,
уровень 1/2/3, «Правда или ИИ» 6 роликов A–F с разгадкой (галочка на правильном варианте —
поле `reveal`), «фото или ИИ» пары 1 и 2, год термина «ИИ» 1956/1986/2012, плюсы («+» —
одна строка-счётчик), оценка эфира 1–10 (среднее досчитывается числом), развилка «что бы вы
сделали». Открытые ответы («сделай за меня…») идут обычными пузырями, без карточки.

## 11. Реакции — рисованные и живые

Источник — `chat.txt` Zoom (127 реакций с временем и целевым сообщением, `chat/reactions_parsed.json`).
Каждая реакция — рисованная иконка в скетч-стиле колоды (`icons.tsx`): сердце, огонь, смех,
палец вверх, хлопок, хлопушка, «100», звезда. Иконка дорисовывается контуром за 10 кадров,
заливка ложится со сдвигом (как маркер), взлетает на 300 px из низа колонки чата с
покачиванием и поворотом, живёт 70 кадров. Пачки реакций дают естественный «салют» из
нескольких иконок; одновременно растёт значок-счётчик на пузыре. Без колонки чата иконки
поднимаются от камеры или от угла окна. Слайд и демо не перекрываются дольше чем на полсекунды.

Звёздочки-дудлы у лица на ярких моментах — отдельный элемент (`doodles: stars`), это не
реакции зрителей и за реакции не выдаются.

Реакции Zoom, видимые прямо в кадре записи (всплывающие эмодзи на плитке), в этой задаче
**не проверялись** — это делает сборщик EDL по кадрам (Gemini, шаг 2 с) и дублирует их тем же
видом иконок в момент появления.

## 13. Интро (≈23 с) и аутро (16 с)

**Интро** (`sc1_intro`): 0–2,4 с знак V рисуется по контуру → 2,4–8 с титул «Проснись, **Нео**»
с маркерным штрихом, имя и роль, а справа живым скетчем рисуются красная и синяя таблетки
со слайда 3 колоды (тот же движок, `sketch/003.json`) → на 8 с — удар музыки (подъём трека
совмещён со стартом тизера) → с 8 с окно вырастает из центра в studio и идут 3 лучших
момента по 4–6 с, каждый в своей обработке: живой скетч слайда 29 («30 шагов…»), board с
рукописной подписью «песок = кремний», стрелкой в слайд и маркерным штрихом под «Мы научили думать
песок», face_xl на шутке «я сегодня настоящий». Метка
«ЛУЧШЕЕ ИЗ ЭФИРА», реальный чат этих минут, уход в первый план эфира.

**Аутро** (образец `stills/Outro_f150.png`): «Хотите на интенсив — пишите» + коралловая кнопка
**`<ссылка>`**, карточка «Следующий бесплатный эфир — `<день, дата, время>`»,
«`<Бот: ссылка>`», QR на бумажной карточке; лесенка 0/0,4/1,0/1,8/2,4 с, держится
≥ 8 с, уход в чёрное 12 кадров.

**Музыка.** Одна спокойная тема без вокала (lo-fi/эмбиент ~96 BPM): одна −20 LUFS, под голосом
на 10 дБ тише, вход 0,5 с, уход 1 с. Только под интро, аутро и карточками глав. Трек
генерируется локально (ACE-Step, навык ace-step) — статус в разделе 17.

**Звук программы:** −16 LUFS, true peak −1,5 dBTP; голос highpass 80 Гц + компрессор −20 дБ
2,5:1; кроссфейд 20 мс на каждом шве; части P1/P2 поднимаются на +5,4/+4,7 дБ до склейки
(замер align-агента в `timeline.json → loudness`).

Четыре отрывка (`style/showcase/final/`) прошли 4 круга «рендер → кадры глазами → Gemini
3.8-flash против эталона → правка». Что поймано и исправлено:

| Круг | Найдено | Исправлено |
|---|---|---|
| кадры r1 | стрелки дудлов пересекали текст слайда; наезд на барабан резал заголовок; тег поверх интерфейса барабана; звёзды поверх шапки чата; цвет текста на плашке «прыгал»; метка «ВОПРОС» на не-вопросах | маршрут стрелок по пустым полям, кадр наезда между строками, теги только над пустыми углами, текст на плашке идёт по краю плашки |
| Gemini r1 | в интро звук уехал на 8 с | ошибка сведения (`adelay` в `amix` сдвигал начало) → `asetpts`+`aresample first_pts=0`, все отрывки пересведены, громкость — двухпроходный loudnorm (−16,0 ±0,2 LUFS) |
| Gemini r1–r2 | пустая плашка имени 5 кадров; ручка исчезала рывком; опрос наезжал на пузырь; после карточки главы «вспыхивал» пустой кадр; наезд на экран итогов резал ники; нет крупного плана лица | текст плашки входит вместе с ней; ручка паркуется и гаснет за 4–5 кадров; карточка опроса разворачивается вместе со списком; карточка прозрачнеет на сворачивании, слайд рисуется под ней; наезд на итоги заменён прожектором + штрихом; добавлен план face_xl |
| Gemini r3 | 5 с почти пустого чёрного слайда после карточки; слайд 8 мелькал 0,6 с во время морфа | ракеты рисуются сразу после карточки (110 кадров, с ручкой); слайд 29 держится до конца морфа, слайд 8 входит кроссфейдом |

даёт); реакции Zoom, видимые в самом кадре записи, не сверялись; тост вопроса в плане full и

## 16. Архитектура рендера и замеры

**Решение — архитектура E:** одна полнокадровая композиция Remotion `Program`, которой
управляет EDL (JSON: планы, источники с наездами и пометками, живые скетчи, камера, чат,
опросы, реакции, дудлы, цитаты, главы, победители, конфетти). ffmpeg делает только вход
(4K → клипы 2560×1440 и 640×360 с переводом 601→709, NVENC) и выход (склейка кусков
`concat -c copy`, звук сводится отдельно и подкладывается в конце).

Почему не ffmpeg-композит (варианты C/D из v1.2): они быстрее, но ради скорости резали то, что
владелец велел оставить (живые скетчи, пометки в координатах слайда, наезды с пометками,
реакции). На свободной машине полнокадровый Remotion и так укладывается в вечер.

Замеры (все — эталонная машина: ноутбук Intel Ultra 9 185H, 22 потока, RTX 4090 Laptop):

**Ранние замеры (v1.2, машина занята другими задачами на ~90 %, BELOW_NORMAL):** CLI Remotion
на кадр 1,25 fps (95 % — запуск CLI); node-процесс полный кадр 4,2 fps; ffmpeg-композит на CPU
3,8–5,6 fps; на GPU (NVDEC → scale_cuda/overlay_cuda → NVENC) 17,9–29,2 fps; вход 4K → 1600×900
90 fps, вырез камеры 115 fps. Вывод тогда был «только ffmpeg» — он отменён установкой владельца.

**Свободная машина после перезагрузки (24.09, 14:40):** прототип 20 с полным кадром Remotion
(один node-процесс, gl=angle): c8 31,2 fps, **c16 32,4 fps**, c22 29,5 fps; слой-оверлей PNG c16 56,5 fps
(`style/proto/speed_node.jsonl`, `bench_free.log`).

**Программа `Program` (архитектура E), шоукейсы, один процесс, c16, gl по умолчанию:**

| Фрагмент | Кадров | Секунд | fps | concurrency |
|---|---|---|---|---|
| sc1_intro | 582 | 19.8 | **29.35** | 16 |
| sc2_poll | 1112 | 42.7 | **26.05** | 16 |
| sc3_chapter | 1249 | 52.9 | **23.62** | 16 |
| sc4_drum | 945 | 67.1 | **14.08** | 16 |

**Два процесса одновременно, c10 каждый, gl=angle** (как будет на полном рендере):

| Фрагмент | Кадров | Секунд | fps | concurrency |
|---|---|---|---|---|
| sc3_chapter | 1249 | 53.4 | **23.39** | 10 |

| sc2_poll | 1112 | 36.5 | **30.44** | 10 |

Стена двух процессов: 3888 кадров за 102 с → **38.1 fps суммарно**
(против 21.3 fps у одного процесса c16 на тех же четырёх фрагментах). Повтор того же прогона
после правок (r5, 15:31) дал **25.6 fps суммарно** (152 с): машину делят другие сессии (в этот
момент ~120 процессов node), поэтому планировать надо по нижней цифре.

Сколько процессов (замеры 24.09, 15:31–15:52, машина общая):

| Схема | Материал | Кадров / стена | Суммарно |
|---|---|---|---|
| 1 процесс c16 | 4 отрывка | 3888 / 182 с | 21,3 fps |
| 2 процесса c10 | 4 отрывка | 3888 / 102 с и 152 с | 38,1 и 25,6 fps |
| 3 процесса c7 | 3 отрывка без Zoom-кадра | 2943 / 67 с | **43,9 fps** |
| 4 процесса c6 | 4 отрывка | 3888 / 150 с | 25,9 fps |

Вывод: 2–3 процесса; четвёртый уже мешает (22 потока, Chrome на кадр съедает свои). Отрывки
с Zoom-кадром 2560×1440 в 1,5–2 раза медленнее слайдовых.

Что тормозит: фрагменты с Zoom-кадром 2560×1440 (барабан, демо) — декод OffthreadVideo и наезд,
~14–17 fps на процесс; слайды, скетчи и чат — 24–30 fps. GPU в рендере почти не занят (Chrome
рисует CPU+ANGLE), он нужен на входе (NVDEC/NVENC).

План полного рендера:

Итоговая длина ≈ 2:02:19 эфира + интро 23 с + ~10 карточек глав по 3,6 с + аутро 16 с ≈
**185 400 кадров**. Примерно 70 % — слайды/скетчи/лицо (≈25 fps на процесс), 30 % — Zoom-кадр
демо и розыгрыша (≈15 fps на процесс).

| Схема | Оценка времени |
|---|---|
| один процесс c16 | 0,7·185 400/25 + 0,3·185 400/14 ≈ 9 200 с ≈ **2 ч 35 мин** |
| два процесса c10 (замерено 25.6–38.1 fps суммарно на смеси) | ≈ 185 400 / 25.6…38.1 ≈ **81–121 мин** |
| три процесса c7 | 43,9 fps на слайдах; смесь ≈ 1/(0,7/44 + 0,3/25) ≈ 36 fps → **≈ 86 мин** |

Порядок работ полного рендера: (1) вход — клипы 2560×1440 и камера 640×360 из 4K для всего эфира
через NVENC (≈ 90 fps, ~35 мин на обе части, можно параллельно с (2)); (2) сборщик EDL на весь
эфир по `build_edl.py` (главы, планы, пометки, опросы, реакции); (3) куски по 5 минут, 2–3
процесса `render_program.mjs` одновременно, готовые куски пропускаются при перезапуске;
(4) проверка кусков кадрами по мере готовности; (5) склейка `concat -c copy`, звук
`mix_audio.py` (loudnorm в два прохода на полном миксе). Чтобы успеть к 20:00 МСК с проверкой
и склейкой, рендер нужно запустить не позже ~17:00 (нижняя оценка 2 ч) — резать объём работы
нельзя, можно только добавить процессов.
