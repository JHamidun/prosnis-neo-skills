# Монтаж эфира: гочи (симптом → причина → лечение)

Справочник к `webinar-montage.md`. Формулировки симптомов — такими, какими их увидели, чтобы по ним находили.
Номера (G-A1 …) используются в коде (`scripts/webinar/**`) и в основном описании пайплайна.
Всё ниже найдено на реальном монтаже двухчасового эфира (2 записи Zoom + диктофон, 185 тыс. кадров) 23–24.09.2026.

## Звук и выравнивание

| # | Симптом | Причина | Лечение |
|---|---|---|---|
| G-A1 | Почищенный кусок диктофона на стыке с Zoom «чуть позже»: слова дублируются или проглатываются | `firequalizer` (zero_phase выкл.) + lookahead `alimiter` дают постоянную задержку **38,0 мс**; `-ss/-to` её не компенсирует | декод с пре-роллом 1 с → обработка → лаг GCC-PHAT против исходника (16 кГц, 200–5000 Гц) → `atrim=start_sample=round((PRE+lag)*48000)`; остаток −0,01 мс (`align/process_recorder.py`) |
| G-A2 | `loudnorm` в один проход на коротком куске ушёл в динамический режим — «качает» | однопроходный loudnorm на коротком/неровном материале | для кусков — статичное усиление + лимитер; для мастера — два прохода (`print_format=json` → `measured_*` + `linear=true`): −16,0 ± 0,2 LUFS против ±0,7…1,4 у одного прохода |
| G-A3 | Свёл голос кусками + музыку — микс короче на задержку первого куска (23,3 → 15,3 с), после `-shortest` видео обрезано, голос уехал на 8 с | `adelay` на ветках многовходового `amix` сдвигает старт вывода на PTS первого голоса; `atrim` режет по абсолютному PTS | на каждой ветке `asetpts=PTS-STARTPTS+{at}/TB,aresample=48000:async=1:first_pts=0,apad=whole_dur={dur}` (`audio/mix_excerpt.py`) |
| G-A4 | Скачок громкости ~5 дБ на стыке интро (диктофон) → запись Zoom | записи Zoom −21,4 / −20,7 LUFS, куски диктофона нормированы к −16 | статичный подъём частей Zoom до склейки (+5,4 / +4,7 дБ по замеру `ebur128`, `edl_config.gain_db`), потом общий loudnorm |
| G-A5 | Сдвиг части к эталону «плывёт» кусками по 0,05–1,3 с | не дрейф часов (часы диктофона и Zoom совпадают < 1 ppm), а провалы сети Zoom — ступеньки | кусочная карта сдвигов по плотному GCC (`align/offmap.py`), а не одна линия; стыки уточнять коротким окном (`align/junction.py`) |
| G-A6 | Грубый поиск дал сдвиг 6010,0 вместо 6008,296 | пик на краю окна поиска | расширить окно; признак — пик ровно на границе диапазона |
| G-A7 | Для двухчасового ролика amix из сотен входов не собирается / тормозит | один вход на кусок | голос — одна цепочка concat с тишиной, посчитанной в сэмплах от `at_s`; музыка — две чередующиеся цепочки; в amix 3 потока (`audio/mix_full.py`) |
| G-A8 | Сведение всего ролика «висит»: за 37 минут ffmpeg набрал 149 с процессора | ffmpeg запущен с BELOW_NORMAL, а рендер-воркеры держат CPU на 100 % — он получал 0,05 ядра | сведение — с обычным приоритетом (`mix_full.py --priority normal`, по умолчанию) или до/после рендера; в эталоне процесс пришлось поднять до AboveNormal |
| G-A9 | Второй проход loudnorm отчитался `normalization_type: dynamic` | измеренные LRA/TP не дали линейного усиления | не паниковать: проверка — итоговые цифры (эталон: −16,0 LUFS, −1,5 dBTP, LRA 3,3); `mix_full.py` сам падает, если мимо цели > 0,3 LU |

## Расшифровка

| # | Симптом | Причина | Лечение |
|---|---|---|---|
| G-T1 | Субтитр висит секунды в тишине; караоке-подсветка слова тянется до 12 с | Deepgram nova-3 растягивает КОНЕЦ последнего слова перед паузой до начала следующей реплики (150+ слов > 1,6 с, 17 > 3 с); начало слова почти всегда верное | `tighten()`: кап `min(max(0.6, 0.09·букв + 0.5), 1.6)` с; длиннее — конец = первая тишина ≥ 200 мс (−42 dBFS, кадры 20 мс); перекрытие — по `start` следующего; исходный конец в `end_raw`; звук читать один раз целиком (`transcript/build_outputs.py`) |
| G-T2 | После правки ASR (несколько токенов → один) порядок слов по `start` ломается, перекрытия | замена меняет число токенов | прижимать интервал замены к началу следующего слова; проверка «0 немонотонных, 0 перекрытий» после сборки |
| G-T3 | Имя ведущего пропало из субтитров: «прошёл курс с, даже…», «уже мало» вместо «у <Имени>» | Deepgram (ru) глотает или коверкает редкие имена | сверка faster-whisper large-v3 (CUDA, `word_timestamps`): от Whisper брать только слова, время — от Deepgram + RMS; признак — служебное слово аномальной длины (`transcript/whisper_crosscheck.py`) |
| G-T4 | Реплики разорваны на куски | утверждения Deepgram фрагментированы | склеивать одного спикера при паузе ≤ 2,5 с |
| G-T5 | Старый код Deepgram SDK падает | SDK 6 сломал прежний API | REST `POST /v1/listen?model=nova-3&language=ru&diarize=true&…` напрямую |
| G-T6 | Малые числа цифрами («1», «2») в живой речи | `smart_format` | второй проход без `smart_format/numerals`, оттуда прописью |
| G-T7 | Короткий клип начинается «А что ещё?» вместо «Хочу ещё» | граница слова Deepgram на ~30 мс позже реального приступа + фейд | границы коротких клипов — в паузе между словами, не по `start` слова; ловится только распознаванием ГОТОВОГО файла |

| # | Симптом | Причина | Лечение |
